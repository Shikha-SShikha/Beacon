# Semantic Enrichment Pipeline

Sequential steps applied during ingestion to transform raw article XML into semantically rich chunks ready for retrieval. Runs once per article at indexing time — not at query time.

| Step                                                     | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Failure modes handled                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. XML Parsing & Structure Extraction**                | Parses Elsevier DTD v5.7 XML (stripping DOCTYPE declarations that block standard parsers). Extracts metadata (DOI, authors, date, abstract, keywords) and splits body into paragraph-level chunks per section. Section roles normalised to: introduction, methods, results, discussion, conclusion. Tiny consecutive paragraphs merged. One-sentence overlap prepended to each chunk from the previous paragraph. Figures and tables extracted separately from `<ce:floats>`.                                                                      | DTD parsing failure; paragraph fragmentation (near-empty chunks); cross-chunk evidence loss where a finding spans a paragraph boundary                                                                                                                                                                                                                    |
| **2. Contextual Prefix Generation**                      | Each text chunk gets a one-sentence AI-generated prefix: *"This results section from [Title] ([Author], [Year]) covers the effect of METTL3 knockdown on m6A levels in Theileria-infected macrophages."* Encodes article title, first author, year, journal, section type, and what the chunk covers.                                                                                                                                                                                                                                              | Decontextualisation — orphaned paragraphs that reference earlier content carry no meaning in isolation; section-blind retrieval — methods and results paragraphs on the same topic are now distinguishable; author/recency blindness — prefix injects authorship and year into the vector                                                                 |
| **3. Figure & Table Claim Extraction**                   | Figures and tables receive an AI summary written as a factual scientific claim rather than a description. *"METTL3 knockdown reduces m6A levels by ~60% in TBL20 cells..."* not *"This figure shows a western blot..."* Specific values, fold-changes, and comparisons are extracted explicitly.                                                                                                                                                                                                                                                   | Figure invisibility — baseline stores `[IMAGE]` placeholders, making quantitative findings unretrievable; caption-only matching — captions describe what a figure contains, not what it proves; quantitative evidence loss — percentages and statistics that live only in figures never enter the retrieval index                                         |
| **4. Named Entity Recognition + Ontology ID Resolution** | Two-stage NER: GPT-4o-mini extracts entity names and types (GENE, DISEASE, CHEMICAL, CELL_LINE, ORGANISM, METHOD), then API resolvers assign canonical ontology IDs with fallbacks: NCBI Gene → genes/proteins; NLM MeSH → OLS Disease Ontology → diseases; NLM MeSH → OLS ChEBI → chemicals; Cellosaurus → cell lines; NCBI Taxonomy → organisms. Output: `[GENE: METTL3 \| NCBI Gene:56339]`, `[CHEMICAL: m6A \| ChEBI:CHEBI:21891]`. ~85% ontology ID coverage on biomedical articles. In-memory cache avoids duplicate API calls within a run. | Synonym drift — `m6A`, `N6-methyladenosine`, `m⁶A` all resolve to the same ChEBI ID; abbreviation opacity — `PAI-1`, `YY1` are opaque to a general embedder; cross-paper entity fragmentation — without canonical IDs, METTL3 in two papers are just similar strings                                                                                      |
| **5. Semantic Relation Extraction**                      | GPT-4o-mini extracts typed subject-predicate-object triples per chunk using extracted entities as anchors. Up to 5 triples per chunk with verbatim evidence snippets. Domain-specific predicate sets per journal: biomedical (methylates, inhibits, activates, binds to…), social science (influences, mediates, predicts…), engineering (optimises, increases efficiency of…). Example: `(METTL3, methylates, m6A)`.                                                                                                                              | Entity co-occurrence without relationship — two entities in the same chunk doesn't mean they interact; implicit finding retrieval — "knockdown of X reduced Y" becomes explicit `(X, reduces, Y)`; query-predicate mismatch — "what inhibits X" matches a chunk asserting `(Y, inhibits, X)` even without that phrasing                                   |
| **6. MeSH Hierarchy Traversal**                          | After MeSH ID resolution, queries the NLM MeSH SPARQL endpoint for parent descriptor terms via `meshv:broaderDescriptor`. Example: tropical theileriosis → Theileria Infections → Protozoan Infections → Parasitic Diseases. Broader terms stored on the entity and serialised as `skos:broader` in JSON-LD.                                                                                                                                                                                                                                       | Specificity mismatch — researcher queries at genus level while articles use species-level terminology; vocabulary siloing — each paper uses its own precise terms, hierarchy traversal normalises upward to shared parent concepts                                                                                                                        |
| **7. Figure-Claim Cross-Linking**                        | Text chunks citing figures/tables (`"as shown in Figure 3"`) are linked bidirectionally to the corresponding figure/table chunk via regex on figure labels. Text chunks get `figure_refs`, float chunks get `cited_in`. At retrieval time, linked figures are fetched and appended as supporting context before LLM synthesis.                                                                                                                                                                                                                     | Evidence fragmentation — finding in text, data in figure; without linking retrieval returns one without the other; orphaned figures — a figure with rich quantitative content may not match the query string directly, but its citing text chunk will                                                                                                     |
| **8. JSON-LD Serialization (schema.org)**                | Each article serialised as a `schema:ScholarlyArticle` with `@id` from its DOI. Entities get canonical `@id` IRIs pointing to their authoritative ontology sources (NCBI Gene, MeSH, DOID, ChEBI, Cellosaurus). Relations stored as `beacon:Relation` triples. Broader MeSH terms as `skos:broader`. Entities deduplicated at article level. Output: portable `.jsonld` files in `jsonld/`.                                                                                                                                                        | Enrichment lock-in — without serialisation all semantic enrichment is internal pipeline state; entity deduplication — same entity in 12 chunks produces one `schema:mentions` entry, not 12; knowledge graph interoperability — entity IRIs resolve to live ontology records, enabling traversal to Wikidata, PubChem, UniProt without re-querying Beacon |
